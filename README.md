# 3Dblocks

立方体グリッドにブロックを積み、そろった列/面を消す 3D パズルゲーム。
スマホのブラウザ向け(three.js 使用)。基調はミニマルで、色がつくのはブロックだけ。
文字は少しだけ丸っこい書体(SF Pro Rounded / 丸ゴシック / M PLUS Rounded 1c)。
スコアが伸びるとドーム(背景)ごと色合い(トーン)が変わっていき、
右上のボタンでいつでも背景が真っ黒のダークモードにできる。

ピースは3軸に広がる立体ポリキューブ。1マス〜直線・L・T・S/Z などの平面形に加え、
3方向コーナーやねじれ階段などの立体形、2×2×2・3×3 平面・3×2×2、
さらに 3×3×3(27マス)の大きな立方体まで「むずめ」の形も登場する。
各ピースは生成時にランダムな向き(3D回転)で現れ、いまのトーンのパレットから 1 色をまとう。

## モード

タイトルで2つのモードを選べる(それぞれ別ランキング)。

| モード | グリッド | 消える条件 |
| --- | --- | --- |
| **ライン** | 5×5×5 | いずれかの軸で1列(5マス)そろうと、そのラインが消える。全ピース(3×3×3含む) |
| **プレーン** | 5×5×5 | 軸に垂直な1面(5×5=25マス)がすべて埋まると、その面が消える。面を埋めやすいよう大きすぎるピースは出ない |

グリッドサイズ・出題ピースの上限・クリア条件は [`js/config.js`](js/config.js) の `MODES` で調整できる。

## 遊び方

| 操作 | 動作 |
| --- | --- |
| 1本指ドラッグ(何も持っていない) | 視点の回転 |
| 1本指ドラッグ(かけらを持っている) | ピース移動。置ける場所に近づくと自動スナップして仮表示、指を離すと確定 |
| トレイの上まで指を戻す | 配置キャンセル(手持ちに戻る) |
| 2本指ピンチ | ズームイン / アウト |

- **初期視点は少し引いた位置**から始まる(`js/game.js` の `CAM_R0`)。
  近すぎると盤面の手前側がトレイの高さまで下がってしまい、そこへ置こうとしても
  「トレイへ戻す=キャンセル」になってしまうため。ピンチでいつでも寄れる
- ピースは**床**か**すでに積まれたブロック**に接する場所にだけ置ける
- X・Y・Z いずれかの軸で1列そろうとそのラインが消える(複数同時でボーナス)
- **仮置き中は、消える列/面のブロックが金色に光って場所を予告**する
- **消える瞬間はレインボー・ルーレット**: そろったブロックが、虹色をルーレットのように
  切り替えながら点滅して弾ける。マスごとに色をずらすので、虹が列/面を走って見える。
  だんだん速く回って、全体で 1 秒ほど(`ROULETTE_SEC` / `ROULETTE_POP` / `ROULETTE_SPINS`)
- **演出はプレーを待たせない**: 消えるのが確定した瞬間に、そのブロックは盤面から
  完全に切り離される(当たり判定も影も消える)。**虹色に光っている最中でも、そのマスには
  もう次のピースを置ける**。演出はゆっくり見せつつ、テンポは落とさない
- **コンボが続くと色が変わる**: 連続で消している間は、消すたびに**盤面のブロックと
  ネクストの色がまとめて一段ずれる**。連鎖しているのが目で分かる
- **全消しのときだけ特別な演出**: 画面全体の虹色フラッシュ + 盤面の中心から広がる
  虹色のリング3枚 + 立方体まるごとから噴き上がる虹色の粒 +
  「全消し!」の虹色グラデーション特大トースト + 強めのシェイクと長い振動
- **仮置き先の選び方**: 「画面の上で指にいちばん近いマス」を主役に、奥行きの意図
  (手前の床か、積み上がったブロックの上か)を光線の当たり点で補って決める。
  さらに、いま吸い付いている場所を少し優遇する(ヒステリシス)ので、指が数px ブレても
  仮置きが別の場所へ飛ばない。**指を離す瞬間にズレることもない**
- **キャンセル判定は「狙っている点」で見る**。指より少し上を狙う仕様のため、
  盤面の手前側を狙うと指がトレイの高さまで下がる。以前はそれだけで
  「トレイへ戻す=キャンセル」と判定され、手前に置けないことがあった
- 手持ち3つのどれも置けなくなったらゲームオーバー
- プレイ中に**左上のホームボタン**を押すと、まず確認が出る。
  「**← ゲームにもどる**」でそのまま続けられ、「ホームへもどる」を選んだ場合も
  **盤面とスコアはセーブされる**ので、タイトルの「つづきから」で同じ続きを再開できる
  (押し間違いで進行が消えない)
- **右下のすきまボタン(👁)**を押すと、埋まっているブロックはすべて消えて(完全に透明)、
  空いているマスだけが**中身のつまった金色のブロック**で示される。
  透けないので、空間のどこがどう抜けているかが一目で分かる
- **詰んでゲームオーバーになると、最後の手をどう置けば詰まなかったか**を、
  人が操作しているように**動画で自動再生**する(配給時点の盤面へ巻き戻し、ディーラーが
  保証した「3つとも置き切れる並び」を、ピースが上空から降りて置かれ、消去演出も本物で見せる)。
  再生中は元々埋まっていたブロックを**外枠だけ(元の色)**にして解の手だけ色付きで際立たせる。
  速度は `js/game.js` の `SOL_SPEED`(現在 **1.5倍速**)で調整できる。
  再生中に**すきまボタン**を押すと、既存ブロックの表示を
  「外枠だけ ⇄ いつもの塗りつぶし」で切り替えられる(初回だけ吹き出しで案内)。
  再生の途中でも**「結果へ →」で結果画面へ / 左上のホームボタンでタイトルへ**抜けられる
  (自己ベスト更新時だけは、記録のため結果画面で止まる)
- **ゲームオーバー画面**からは「もういちど / ホームへ戻る / ランキング」に進める
  (自己ベスト更新時は、なまえを記録してから)
- **中断復帰**: アプリを閉じても、次に開くとタイトルの「**つづきから**」で
  前回の盤面・スコアから再開できる(端末に自動セーブ)
- **自己ベストを更新したら、なまえを記録するまで次のゲームに進めない**

### ダークモード

- 右上の**月/太陽ボタン**でいつでも切り替えられる。**背景が真っ黒**になり、
  ブロックの色だけが浮かび上がる
- 暗い間は**文字・アイコン・トレイの色を明るい側へ自動で反転**する。
  白いパネルのオーバーレイ(確認ダイアログ・結果画面など)の中だけは元の色に戻すので、
  どちらのモードでも読みやすさは変わらない。ブラウザのバーの色(theme-color)も合わせる
- トーンより優先される(蛍光トーンでも背景は黒のまま)。設定は端末に保存される

### 色合い(トーン)とドーム

ブロックの柄(ストライプ/ドット)は廃止して、**色合いそのものをご褒美**にした。

- **1トーン = 「同じ色familyの8色 + その色に合うドーム(背景)と舞台」のセット**。
  デイライト / **ビビッド** / サンセット / **ネオン** / オーシャン / **オーロラ** /
  フォレスト / トワイライト / シトラス の9種類
- **彩度の高いトーンと蛍光色のトーン**もある:
  - **ビビッド**は原色そのままの高彩度。ドームをあえて素っ気ない灰白にして色を立たせる
  - **ネオン / オーロラ**は蛍光色。**ドームが暗くなり、ブロック自身が光っているように見える**
    (発光を強め、映り込みとライトを落として、蛍光が沈まないようにしている)。
  - 暗いドームの間は **HUD の文字やボタンの色が自動で明るい側へ反転する**ので読みやすさは変わらない
    (白いパネルのオーバーレイの中だけは元の色に戻す)
- **スコアが一定を超えるたびに次のトーンへ変わる**。ドーム(背景のグラデーション)も、
  **場に積まれているブロックも、ネクストの3つも、まとめてその色合いに着替える**
  (色はふわっと補間される。切り替わったらトーン名がトーストで出る)
- ピースは色そのものではなく「パレットの何番目か」を持っていて、表示するときに
  いまのトーンの色へ引き当てる。だから途中でトーンが変わっても盤面がちぐはぐにならない
- 何点ごとに変わるかはモード別 (`js/config.js` の `TONE_STEP`。ライン 3500 / プレーン 200)。
  計測した中央値の1ゲームで6種類前後を通る。並び順も、彩度の高いトーンや蛍光トーンが
  早めに出るように混ぜてある
- 色を足したい・変えたいときは `TONES` に基準色を並べるだけでよい
  (発光色と輪郭色は自動で作られる)。トーンごとに `dark` / `emissive` / `env` / `light`
  を足せば、暗いドームや光り方まで変えられる
- 一周したら先頭のトーンへ戻る(スコアが伸びるほど何周もする)

### ピース配給(スマートディーラー)

3つの手持ちは完全ランダムではなく、盤面をより賢く読んで配る:

- 「あと少しで消える列/面」にはまるピースを混ぜて気持ちよく。読みの精度を上げ、
  **一手で複数の列/面を同時に完成できる置き所**があるピースを特に高く評価する
  (ただし3つ全部は正解にせず、どれがどこにはまるかは自分で気づく余地を残す=
  良い手が出過ぎて単調にならない塩梅)
- さらに次の観点まで見て「いま欲しい一手」を勘ぐる:
  - **残り穴が少ないグループほど強く狙う**(完成まであと1マスの列に刺さる形は最優先)
  - **お膳立て**: 置いたあと「残り1〜2マス」になる置き所も評価(次の一手が見える)
  - **死に穴を作らない**: 置いた結果まわりを完全にふさがれて二度と埋められなくなる空きが
    できる置き方は大きく減点する(盤面をじわじわ殺す手を配らない)
  - **3つの狙いを散らす**: 3つとも同じ列を狙う組は、1つ置いた時点で残り2つが用済みに
    なって薄いので避ける
  - **苦しいときは逃げ道を混ぜる**: 盤面が詰まってくるほど「置ける場所が多いピース」を
    高く評価する(余裕があるときは効かせない)
  - この読みの重みは**モード別**。ライン(1列=5マス)は頻繁に消えるので狙いを強くしすぎると
    盤面が荒れて寿命が縮み、プレーン(1面=25マス)は強く狙わないとそもそも消えない。
    A/B計測で両立する値に調整してある(`js/dealer.js` の `READ`)
- **3つとも場に出た時点で、全部を置き切れる手順が最低1つ存在する**ことを解探索で
  保証(最適手順を選べば詰まない)。盤面がほぼ満杯のときは保証なしのフォールバック
- さらに、盤面が埋まってきたら**「置き切れる並びの通り数」が少ない=最適解が絞れる
  締まった組**を優先して配る。序盤のスカスカな盤面では素直に軽く配る
- **ごくたまに、盤面をまるごと空にできる「全消し」の当たり手**を配って最大のご褒美に。
  さらに**たまに大きく消せる(面1枚・複数ライン)当たり手**も(頻度は `js/dealer.js` の
  `FULLCLEAR` などの定数でモード別に調整可能)。
- 全消しは**偶然を待つのではなく逆算して構成する**。「残っているブロックを覆う線/面」を選び、
  その空き部分をちょうど3ピースで敷き詰められるかを解く(`buildClearAllTrio`)。
  空きが低い位置=支えのある所になる覆いを優先する(宙に浮いた空きは置けないため)。
  ただし全消しは幾何条件が厳しく、**残りブロックが薄い時にしか成立しない**
  (計測: 残26マス超はほぼ0%、残16マス以下なら3〜5割)。そのため抽選する帯を
  薄い盤面に絞り、そこでは高確率で狙いにいく(厚い盤面では探索もしないので軽い)
- **全消しチャンスの告知は出さない**: 以前はトレイの上に「✦ 全消しチャンス ✦」の
  バナーを出していたが、**自分で気づいた時がいちばん気持ちいい**ので廃止した。
  ディーラーは仕込むだけで、そのことは画面に出さない
- 出題ピースの平均体積をさらに大きめ(約6.6マス)に寄せ、見た目の歯ごたえを上げている。
  その分の詰みは上の全消し・大消しのご褒美と置き切り保証で救済する
- **段階的な全消し(クリアラン)**: 1手の3ピースで空にできる盤面はごく限られるので、
  そこに届かない場面では**「置けば確実にブロックが減る手」を配り続けて、何手かかけて
  空へ向かわせる**。減らせない場面では「完成まであと何マス」を縮める
  仕込みの手で繋ぎ、それでも記録を更新できない手が続いたら流れは終わる
  (だらだら続いて簡単になりすぎないように)。空にできたら**全消しボーナス**が入る
- **ゲームの入り口**: 開始から数回の配給では、**二分の一の確率で「3つ置き切ると盤面が
  まるごと消える」組**を配る。床の上のライン3本(ライン)/床の面まるごと(プレーン)を
  ちょうど3つに切り分けた形なので、床の上だけで完結して必ず置ける。
  導入からいきなり全消しの気持ちよさを味わえる
  (頻度は `OPENING_PROB` / 対象の配給回数は `OPENING_DEALS`)
- **プレーンの「絶対ここに置くだろ」イベント**: たまに、**残っているブロックを覆う面/線の
  空きを、その形のまま3つに切り分けて**配る。どのピースも穴の形そのものなので置き場所に
  迷わず、素直に置いていくと**気づいたら全消しになっている**。
  仕上げの手順が本当に成立することを、置く順を総当りして確認してから配る
  (`buildObviousClearTrio` / 頻度は `OBVIOUS_PROB`)
- **分離した空きにぴったりはまる形**: まわりを完全に囲まれた小さな空き
  (=空きの連結成分として孤立した4マス前後の空間)を見つけたら、
  **その穴の形そのままのピース**を作って必ず手札に入れる。
  ライン/面が消えるかどうかとは無関係に配るので、「この穴のための形だ」という
  収まりの気持ちよさが独立したご褒美になる(`POCKET_MAX` / `POCKET_BONUS`)
- **空欄の形から作るピース**: 「消える所にはまる形」を探すだけでなく、**盤面の空きそのものを
  読んで、その隙間にぴったり収まる形を作って配る**。既存ブロックや床によく面している空きから
  形を育てるので、「ここに入れてほしかった形だ」という収まりの良さが出る。
  既存の形の一覧に無い形も作れる(`GAP_CANDIDATES` / `GAP_MIN` / `GAP_MAX` で調整)
- **形が足りなくて詰むことをなくした**: 既存の形の中に「3つとも置ける組」が無い場合、
  以前は置けるか確認せずランダムに配っていたため理不尽な詰みが起きていた。
  いまは**いまの空きに必ず収まる形を新しく作って配る**。1つ置いた前提で次を作るので、
  「3つとも順に置ける」ことが構成上保証される
- **たまに罠**: 「**置ける場所はたくさんあるのに、その大半が置いた瞬間に詰む**」組を配る。
  簡単そうに見えて置き場所の判断が効く、という歯応え。最初の一手として選べる置き方を
  実際に(消去も込みで)シミュレートし、生き残る割合が低い組を選んでいる。
  生き残る手が1つも無い組は配らないので**正解は必ず存在する**。
  調整は `TRAP_PROB` / `TRAP_MAX_RATIO` / `TRAP_MIN_FILL`
- **たまに難問**: ときどき「**正解がほぼ一つしか無い**」組を配る。
  外すと詰むので、置き場所をよく考える必要がある。
  置き切れる並びの通り数が 0(配られた時点で詰み)の組は絶対に配らないので、
  **正解は必ず存在する**。外して詰んでも、いつもどおり「こう置けばよかった」の
  自動再生で答えが見られる。頻度は `TIGHT_PROB` / `TIGHT_MAX_WAYS`
- **ラインの難易度を上げる仕掛け**: ラインは1列=5マスで頻繁に消えるため、
  計測すると盤面はほぼ常に1〜3割しか埋まらない(プレーンは0〜8割に広がる)。
  薄い盤面では小さいピースはどこにでも置けてしまい、罠も「正解が一つ」も原理的に成立しない。
  そこでラインでは、
  - 罠/難問を狙うときだけ**大物(8マス以上)のピースを引き直して吟味する**
    (`hardCandidates`)。大物は置ける場所が限られるので、薄い盤面でも
    「置ける場所は多いのに、大半を選ぶと残り2つが入らない」局面を作れる
  - 難問と認める通り数を**ただ一つ**に絞る(プレーンはもう1通りまで許す)。
    盤面が薄くて通り数を絞りきれない時は、「**生き残る置き方がほぼ一つ**」の組で代用する
    (実質、正解は一つ)
  - 罠/難問を狙う確率と厳しさもライン側を厚くしてある
  自動対戦(貪欲AI)での計測では、**1ゲームの長さが約155手 → 約78手**になった
- **good エフェクト**: ディーラーが想定する最適解と同じ位置にピースを置けたときだけ、
  その場所に「good」が弾ける(音つき)。この最適解は**「いちばん点が高くなる手順」**
  (消去・複数同時・コンボ・全消しボーナスまで数えた上での最善)なので、
  **ブロックが消える気持ちいい置き所が正解**になる。1手ごとに引き直すため、
  途中で違う置き方をしても、そこからの最善手に対して good が出る

## 動かし方

ビルド不要の静的サイトです。そのままホスティングするだけで動きます。

```bash
# ローカルで試す
python3 -m http.server 8000
# → スマホと同じ Wi-Fi なら http://<PCのIP>:8000 で実機確認できる
```

GitHub Pages なら: リポジトリの Settings → Pages → Branch にこのブランチを指定するだけ。

## スマホアプリのように使う (PWA)

- **アプリ内ブラウザからの脱出**: LINE 等のアプリ内ブラウザで開くと、LINE は公式の
  `openExternalBrowser=1` で自動的に Safari / Chrome へ飛ぶ。抜けられない環境
  (iOS の Instagram 等)では「ブラウザで開く / URLをコピー」の案内を表示する。
- **全画面表示**: `manifest.json`(`display: fullscreen`)と Apple 用メタタグにより、
  ホーム画面から起動するとブラウザのバーが消えて全画面になる。
- **ホーム画面に追加**: マニフェスト + アイコン + Service Worker(`sw.js`)対応。
  iOS は Safari の共有 →「ホーム画面に追加」、Android は Chrome のインストール案内から。
  Service Worker がシェルをキャッシュするので2回目以降はオフラインでも起動する。
- **アプリアイコン**: `icons/` に 180/192/512(＋マスカブル)を用意。ブランドのブルー地に
  アイソメトリックの3色ブロック。差し替えるときは同じサイズの PNG を置くだけ。

> 注意: PWA 機能(Service Worker / インストール)は **HTTPS**(または localhost)で動く。
> GitHub Pages は HTTPS なのでそのまま有効。ファイルを更新したら `sw.js` の
> `VERSION` を上げるとキャッシュが更新される。

## バージョン

アプリのバージョンは [`js/config.js`](js/config.js) の `APP_VERSION` が唯一の基準で、
タイトル画面の右下に「v◯.◯」と表示される。**マージ(リリース)のたびに +0.1** し、
同時に `sw.js` の `VERSION`(キャッシュ名)も同じ番号へ更新してキャッシュを入れ替える。
現在は **3.5**。

## オンライン世界ランキングを有効にする(約5分)

ランキングは Firebase Realtime Database の REST API を SDK なしで直接使います。
未設定の間は自動的に「この端末のランキング」のみで動作します。

1. [Firebase Console](https://console.firebase.google.com/) で無料プロジェクトを作成
2. 「構築 → Realtime Database」→「データベースを作成」(ロケーションはどこでも可)
3. セキュリティルールを次のように設定:

   ```json
   {
     "rules": {
       "blocks3d": {
         "v1": {
           ".read": true,
           ".indexOn": ["s"],
           "$entry": {
             ".write": "!data.exists()",
             ".validate": "newData.hasChildren(['n','s','t']) && newData.child('n').isString() && newData.child('n').val().length <= 12 && newData.child('s').isNumber() && newData.child('s').val() >= 0"
           }
         }
       }
     }
   }
   ```

   (追記のみ許可・改ざん防止のバリデーション付き。カジュアルなランキング用途を想定)

4. データベースの URL(`https://xxxx-default-rtdb.….firebasedatabase.app` の形式)をコピーし、
   [`js/config.js`](js/config.js) の `RANKING.endpoint` に貼り付ける:

   ```js
   export const RANKING = {
     endpoint: "https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app",
     path: "blocks3d/v1",
     limit: 100,
   };
   ```

これだけで、ゲームオーバー画面から世界ランキングへの登録と閲覧ができるようになります。
ライン/プレーンの2モードは**同じ保存先(`blocks3d/v1`)に mode フィールド付きで記録**し、
表示時にモードで絞り込むので、上記ルールのままで両モードの別ランキングが動きます。

> **注意**: クライアントのみで完結する構成のため、本気の不正対策はできません。
> 友達や世界のプレイヤーとゆるく競うカジュアルランキングとして使ってください。
